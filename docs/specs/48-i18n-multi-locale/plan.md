# Implementation Plan: Multi-locale Support (next-intl)

**Branch**: `feat/48-i18n-multi-locale` | **Date**: 2026-06-27 | **Spec**: [spec.md](spec.md)

**Input**: `docs/specs/48-i18n-multi-locale/spec.md`

---

## Summary

Install `next-intl ^3` and restructure the App Router so all storefront routes live under `src/app/[locale]/`. Default locale (`vi`) uses no URL prefix; English uses `/en/`. A `LocaleSwitcher` client component in the Navbar toggles locales. All UI strings in NavLinks, Footer, and page metadata are extracted to `messages/vi.json` + `messages/en.json`.

---

**Language/Version**: TypeScript 5 / Next.js 14.2 (App Router)

**Project Type**: Web application — i18n routing layer

- Admin routes must remain unprefixed (`/admin`, not `/en/admin`)
- All existing storefront features continue working post-migration
- `tsc --noEmit` must pass after migration

**Scale/Scope**: ~15 route files moved, ~5 new infra files, 2 message JSON files, 1 new component

## Key Design Decisions (from research.md)

1. **`localePrefix: 'as-needed'`** — Vietnamese at `/`, English at `/en/` — best UX for target market.
2. **Admin excluded from middleware** — matcher pattern blocks `/admin/**` and `/api/**`.
3. **Type-safe messages** — `src/i18n.d.ts` wires `Messages` to next-intl; typos in translation keys are compile errors.
4. **Server component Navbar preserved** — `LocaleSwitcher` is the only new client component needed.
5. **Link migration scope** — only storefront components; admin and API files untouched.
6. **Phase B content (product/blog copy)** — deferred; data files retain `Vi`/`En` field pairs from spec 47 ready for a future Phase B pass.

| Existing Zustand cart state breaks   | Low        | Cart store is client-only (localStorage); unaffected by routing layer |
